# CLA 维护说明

当前 [CLA](../../../CLA.md) 为 `0.3-draft` 简版，**未生效、确认流程尚未启用**。本说明用于正式启用后的 PR 人工核查和记录留存。

## 启用前必须完成

1. 确认最终条款和语言安排，包括是否设置适用法律与争议解决专门条款。
2. 将经确认的完整文本定为 **CLA v1.0**，在取得发布授权后提交并发布。保存该实际提交的完整 SHA、文件原文与 SHA-256。
3. 在 [PR 模板](../../../.github/pull_request_template.md) 和 [贡献指南](../../../CONTRIBUTING.md) 填入该真实提交的 CLA 永久链接，替换草案链接和待填说明，再明确解除“尚未启用”门禁。确认项继续默认未勾选，附近保留商业、专有再许可及收购承接摘要，并要求贡献者主动勾选和本人评论。
4. 确定维护者核查与私密记录的负责人、存放位置及必要资料的私密联系渠道，说明数据用途与访问范围。仅在权属或代表权限需要时私密取得补充证明，不要求所有人公开真实姓名。用实际 PR 检查模板展示和人工核查步骤之后启用。

## 固定版本链接

正式协议发布后，在 GitHub 文件页面按 `y` 取得 [指向具体提交的永久链接](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files)，核查 URL 使用真实完整 commit SHA、页面文本确为 CLA v1.0，并保存完整文件和散列。`main`、`HEAD` 和可移动 tag 不作为确认版本。

当前没有可签署的 v1.0 链接。不要把当前 HEAD 填入：当前提交尚不含正式 CLA。启用后的模板应将默认未勾选项写为“我已阅读并同意 CLA v1.0 的英文条款，并确认我有权按该协议授权本 PR 中由我提交的贡献”，紧邻完整协议的固定链接与关键权利摘要。中文解释不是另一个签署文本，记录应包括英文条款及其版本声明、来源和许可说明的完整文件。

正式协议以后修改时，应发布新版本及其实际提交永久链接、更新模板，并取得需要的新确认。已确认版本的原文和记录继续保留；不能用一次旧勾选替换为“同意最新 CLA”。

## 每个 PR 的人工核查

1. 先确认已启用正式版本，PR 中的链接确为指定版本，且当前贡献者是主动勾选者；不得由维护者代勾。草案门禁仍存在、缺少固定版本或记录不清时，不合并需要 CLA 的贡献。
2. 找到贡献者本人账号发布的确认评论，核对其明确同意 CLA v1.0 的英文条款、链接相同，且授权范围指向本次 PR。建议原文为：`我已阅读并同意 CLA v1.0 的英文条款（填写模板公布的固定版本链接），并将本 PR 中由我有权授权的贡献按该协议授权。` 确认本人账号、时间与可用编辑记录，避免将他人转述或单纯 PR 勾选视为完整记录。
3. 核对本次 PR 的相关作者、提交、共同作者和材料来源。每个相关权利人的部分需要对应确认；雇主或公司所有的部分由有权代表授权并记录范围。一个人的勾选或公司账号身份不覆盖其他人、其他公司或所有关联主体。
4. 保存下述最低记录。接收方或其授权维护者完成核查后，在 PR 留下一条简短接受记录，注明协议版本、确认评论链接和核查的 PR head SHA，不放私密资料。
5. 合并前复核 PR 是否新增作者或材料、改变权属或协议版本。普通后续提交仍按明确同意的本 PR 范围核查；超出授权范围或需要新版本时，取得对应的新确认。不能自动覆盖其他历史 PR。
6. 合并后补充实际 merge commit，保留记录并备份。该流程依靠维护者执行，不提供自动状态检查或机器人强制门禁；使用方不能把模板存在等同于核查已完成。

复选框和评论可被编辑；留存核验时的正文、评论及相关元数据，不能只保存 URL。

## 最低留存记录

用一个私密目录或现有私密记录系统即可，不要求新增服务。每个 PR 留存一份记录，可按 `PR 编号/协议版本/贡献者账号 ID` 组织：

- 完整协议文件、版本、永久链接、完整 commit SHA 和 UTF-8 文件 SHA-256。
- 贡献者稳定数字账号 ID、当时用户名、本人评论 URL 和 ID、UTC 创建时间、可见更新时间、确认原文与核验时的 PR 正文快照；如发生编辑，记录检查结果。
- PR 编号和 URL、核查时 head SHA、对应作者及授权贡献范围，合并后补充 merge commit。
- 维护者账号、UTC 核查时间与接受评论链接；记录全部相关作者和版本是否核查通过。
- 仅在需要时保存实体身份、代表权限、雇主同意、共同作者或历史贡献补充授权；有转让时保存承接文件、主体、时间、范围及承接义务。

完整记录和私密证明不提交到公开仓库或 PR 评论。公开可以注明版本已核查及确认评论链接，不公开私密身份或权限文件；没有具体核验需要时，不额外收集姓名、地址等资料。保存完整文本及记录快照并定期备份；散列帮助核对文本一致性，不单独证明谁何时同意。

用户名变化时通过稳定 ID 核对；发现账号持有人或法律主体变化时需另行核查，不能因 ID 相同就推定仍是同一法律主体。记录撤回勾选、删除或修改确认的情况，合并前遇到授权不清先澄清，不静默忽略。
