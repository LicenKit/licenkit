# CLA 维护说明

当前使用 [CLA v1.0](../../../CLA.md)：本版本及提交提示发布后，提交供合并的 PR（合并请求）即表示同意英文条款，并按协议授权本次 PR 中提交者有权授权的贡献。

## 发布与版本

- 协议、贡献指南、PR 模板和 README 随同一次仓库更新发布，无需单独发布 Release 或先发布协议再回填链接。
- 在贡献指南和 PR 模板顶部醒目说明提交即表示同意，并紧邻完整协议链接与商业、专有及多层级再许可和项目转让安排的摘要。
- 通过仓库的 Git 版本历史保留各正式版本的完整协议、对应提交提示和实际发布提交。已发布版本的条款保持不变；修改条款时升版本，同步更新各入口，并保留旧版本。

## 合并前核查

1. 确认 PR 在本版本协议及提交提示发布后提交，适用的协议版本清楚。发布前的 PR 或其他历史贡献需要补充授权时，另行明确范围并取得同意，不追溯推定提交者已经接受后来新增的规则。
2. 核对作者、共同作者及材料来源。提交者只能授权自己拥有或有权许可的贡献；共同作者、雇主或公司拥有的其他部分，由对应权利人或有权代表授权。维护者自身的作品同样核查其实际权利来源。
3. PR 增加作者或材料、改变权属时，再核查相应权限。遇到明确反对条款、授权范围不清或没有权利授予许可的情况，先澄清并取得所需授权，再合并需要 CLA 的贡献。

提交 PR 是约定的同意方式，无需额外勾选或另发同意评论。该方式不替代提交前的清楚提示和实际授权权限，也不提供自动状态检查。

## 记录

常规记录使用仓库版本历史和 GitHub PR 记录：

- 仓库中保留完整协议、版本、提交提示及对应的发布提交。
- PR 中保留提交账号、提交时间、正文、作者和材料来源、所含代码提交与合并记录；有补充授权或范围说明时，在对应 PR 中注明。

常规流程不要求维护者另建私密目录、逐条抄录评论或制作每个 PR 的确认档案。需要核实雇主权利、代表权限等情况时，与贡献者约定私密渠道保管必要证明，不将身份或授权文件公开。

仓库历史和 PR 记录用于核对当时的协议、提示与提交行为，不是不可修改的签署凭证。发生争议时，仍需核查提示是否充分、提交账号及授权权限，不能仅凭存在一个 PR 就认定所有相关权利人都已同意。有项目转让时，按协议保存书面承接文件、主体、时间和范围。
